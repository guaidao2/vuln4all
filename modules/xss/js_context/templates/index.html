这一题的关键：`<script>` 是「原始文本元素」

在 <script> 里面，浏览器只找一件事： </script。所有 HTML 实体都不解码。

&lt;/script&gt;只是普通文本 —— 关不掉 script 元素
</script>原文出现 → script 元素立刻结束

自己验一下：搜 &lt;b&gt;， 然后看页面源码里 script 那一段 —— 它有没有变成 <b>？

过滤器拦的是哪种标签

规则是 <script（开始标签）。 那问题来了：开始标签和结束标签是同一个字符串吗？

页面里真实的那段 JS

<script>
  // ↓↓↓ 洞就在这里：这个值被 json.dumps 处理过，但没做 HTML 层的转义 ↓↓↓
  var recentQuery = {{ embedded }};
  // ↑↑↑ 正确做法：{{ '{{' }} recentQuery | tojson {{ '}}' }} ↑↑↑
  ...写入 localStorage...
</script>

（上面这个方块是转义后显示的 —— 和页面最后那段真实的 <script> 对比着看。）

为什么 json.dumps 不够

它做的是 JS 层面的序列化 —— 它知道这段数据要当 JS 解析。 但它不知道这段 JSON 还要嵌进 HTML 的 script 元素里。

而对 HTML 解析器来说，</script> 的语义不是 「JS 字符串里的几个字符」，是「结束这个元素」。

正确做法是按最终上下文转义 —— Flask 的 |tojson 会把 < 转成 \u003c，正是为了这件事。

{#- 真实的那段 JS：这里没有转义 —— 洞就在 |safe 上。 注意它和上面那个显示用的方块是两回事：方块里必须转义（否则这一页自己中招）， 而这一段正是要展示"不转义会怎样"。 -#} {% endblock %}
