服务端怎么判断这个目标是站内还是站外

两条规则：

一、以 / 开头的 → 算站内相对路径
二、提到了 {{ own_host }} 的 → 算站内

两条规则都在「拦截」那一侧 —— 所以要看的是：有没有哪种写法能 同时满足其中一条、又不是站内。

看 Location 头

curl -i -X POST -d 'user=alice&password=alice123' \
     --data-urlencode 'next=<你想试的写法>' \
     '{{ url_for('login') }}'

登录成功后响应是一个 302，真正的跳转目标在 Location 里。 这一题就靠它判定。

这个洞为什么值得单独学

开放重定向本身不直接泄露数据，但它是钓鱼的放大器： 受害者收到的是自家域名下的链接（`https://自家域名/login?next=//evil.example`）， 点进去登录完之后落到攻击者的站点上。而且它经常和 OAuth / SSO 的 `redirect_uri` 校验一起出现 —— 那才是真正能拿走 token 的场景。
