# 带编码过滤的路径穿越（双重解码）

## 这一题在教什么

**过滤器看到的那串字符串，跟应用最终拿去用的那串字符串，不是同一个。**

这一题有两处要绕，而且是叠起来的：

1. **解码层数不一致** —— 过滤器跑在第一次解码之后，应用自己又解了一次码
2. **黑名单覆盖了文件名** —— 就算路径绕过去了，目标文件名本身也在黑名单里

## 过滤层

```python
RULES = [
    ("上级目录",   r"\.\."),
    ("路径分隔符", r"[/\\]"),
    ("敏感文件名", r"(?i)token|secret|passwd|shadow|\.ssh|\.env|id_rsa"),
]
```

`..` 拦了，`/` 和 `\` 也拦了 —— 直觉上"路径穿越"这条路是封死的。
第三条更狠：目标文件名 `ops-token.txt` 里的 `token` 直接命中。

## 根因在应用这边

```python
name = request.args.get("file", "")

blocked = inspect(name)        # 过滤器：看第一次解码之后的值
if blocked: ...

real = unquote(name)           # ← 应用自己又解了一次码
target = shared / real         # ← 真正拿去拼路径的是这个
```

**Flask 已经解码过一次了。** 所以 `unquote()` 是第二次解码。

过滤器站在两次解码**中间**，于是它的判断基于一个**中间状态** ——
而这个中间状态跟最终值可以差得很远。

越过那一行，应用要两个字符：`.` 和 `/`。
过滤器不让这串字符串里出现它们。
那就让它们**在第一次解码之后还看不出来**。

## 怎么打通

### 第一步：路径用双重编码

```
%252e%252e%252f
```

| 阶段 | 值 |
|---|---|
| 你写进 URL | `%252e%252e%252f` |
| Flask 解码一次（过滤器看到的就是这个） | `%2e%2e%2f` |
| `unquote()` 再解一次 | `../` |

过滤器看到 `%2e%2e%2f` —— 里面既没有 `.` 也没有 `/`。放行。

> 记住 `%25` 就是 `%` 本身的编码。所以 `%252e` 解码一次是 `%2e`，
> 再解一次才是 `.`。

### 第二步：文件名也要编码，但只编**匹配到的那几个字符**

路径绕过去之后，你要读 `private/ops-token.txt`。但 `token` 命中第三条规则。

**编码不需要覆盖整个文件名，只要破坏黑名单的匹配就行。** 把 `t` 换成 `%74`：

```
ops-%2574oken.txt
```

- 过滤器看到 `ops-%2574oken.txt` → 里面没有 `token` 这个子串 → 放行
- 两次解码之后 → `ops-token.txt`

### 完整 payload

```
%252e%252e%252fprivate%252fops-%2574oken.txt
```

注意路径里的斜杠也必须是双重编码的（`%252f`）—— 因为单次解码之后
它就成了 `/`，会被第二条规则拦掉。

## 别背 payload：先搞清楚过滤器是拦还是删

一个很值得记住的对照：

| 过滤器类型 | `....//` 有用吗 | 为什么 |
|---|---|---|
| **删除式**（`re.sub(r"\.\./", "", v)`） | **有用** | 删掉 `../` 之后 `....//` 剩下的正好是 `../` |
| **拦截式**（这一题） | **没用** | 命中就不执行 —— `....//` 里照样含有 `..` |

`....//` 是网上的"经典 payload"之一。它在删除式过滤器上确实有效，
在拦截式上一点用都没有。**先判断性质，再选 payload。**

## 那些已经失效的老技巧

顺手记一下，省得白试：

| 技巧 | 现状 |
|---|---|
| `%c0%ae%c0%ae%c0%af`（超长 UTF-8） | **失效** —— 现代语言的解码器会把它当非法 UTF-8 处理掉 |
| `..%00/`（空字节截断） | **失效** —— 现代语言不允许字符串里出现 `\x00` 当路径 |
| `..%5c`（Windows 反斜杠） | 只在 Windows 上有效，且被第二条规则一起拦了 |
| `....//` | 只对删除式过滤器有效 |
| `..%252f`（只双重编码斜杠） | **不够** —— 点还是明文，第一条规则会拦 |

「知道某个老技巧已经失效了」也是一种知识 —— 它避免你在一个死路上耗时间。

## 怎么修

**一、把用户输入解析成"名字"，而不是"路径"。**

```python
from pathlib import Path

base = Path(shared).resolve()
target = (base / name).resolve()

# 关键：校验解析之后的**绝对**路径还在 base 里面
if base != target and base not in target.parents:
    abort(403)
```

三个细节：

- `resolve()` 把 `..`、符号链接、相对路径全展开 —— 校验要在**展开之后**做
- 比较的是 `Path` 对象，不是字符串。字符串比较会被 `/shared-evil` 这种骗过去
- `base != target` 那个判断是必要的：如果 `target` 就是 `base` 本身，
  `target.parents` 里不含 `base`

**二、只解码一次，而且要在校验之前。**

```python
name = request.args.get("file", "")     # Flask 已经解过一次了
if "%" in name:                          # 还有残留的百分号 → 可疑
    abort(400)
```

**更彻底的做法**：只认白名单里的文件名。

```python
ALLOWED = {"readme.txt", "q1-report.txt", "onboarding.txt"}
if name not in ALLOWED:
    abort(403)
```

如果是动态文件列表，就用**文件 ID 映射**而不是路径：
数据库里的 `id → 真实路径`，用户只能传 `id`。这样用户输入里根本
不出现路径，一整个漏洞类别消失。

**三、别用黑名单拦文件名。**

`token`、`secret`、`passwd`... 这份清单列不完，而且会误伤正常文件名
（比如一个叫 `tokenizer-notes.txt` 的文件）。更重要的是：
**黑名单挡不住编码绕过**，因为编码方式有无穷多种。

**四、过滤层和解码层要"对齐"。**

这一题的根本问题不是"过滤器写得不严"，而是**它看的不是最终值**。
任何校验都必须作用在**真正被使用的那份数据**上。

> 一条通用原则：**输入经过几层处理，校验就要贴着最后一层做。**
> 校验放在中间，中间之后每多一层变换，就多一片盲区。
