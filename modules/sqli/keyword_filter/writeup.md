# 带关键词过滤的 SQL 注入

## 这一题在教什么

**过滤器的每一条规则都有自己的盲区，而盲区是可以一个个试出来的。**

注入手法本身跟 `sqli/login_bypass`、`sqli/union_query` 是同一个洞，甚至更简单。
这一题多出来的东西只有一个：**一份关键词黑名单**。

所以考点是：

> **你的 payload 语法** 跟 **它的匹配模式** 之间的差距，就是绕过空间。

而且这一题的拦截页会把**命中的规则名**告诉你 —— 这等于免费送你一张过滤器地图。
真实环境里没这种好事（你只能靠试），但作为教学，先让你看见规则长什么样，
再让你学会"看见规则就知道怎么绕"。

## 过滤层

`module.py`：

```python
RULES = [
    ("注释",         r"--|#|/\*"),
    ("union select", r"(?i)union select"),
    ("布尔运算",     r"(?i)\b(or|and)\b"),
    ("系统表",       r"(?i)sqlite_"),
]
```

按顺序跑，命中就返回拦截页。注意它是**拦截**（不执行查询），
不是**删除**（删掉命中的部分再执行）—— 这两者的绕过思路完全不同，
后面会展开。

## 一条一条看这些规则漏了什么

### 规则 1：`--|#|/\*` —— 只认字面量

过滤器的作者认为"注释就是攻击特征"。这条规则本身写得没毛病，
但它造成的后果是：**你原本用来收尾的 `-- ` 不能用了。**

那怎么办？不用注释，就得让后面的东西在语法上合法。原始的查询是：

```sql
SELECT name, dept, ext FROM staff WHERE name LIKE '%<你输入>%'
```

注意模板在你输入的**两边**各加了一个 `%` 和 `'`。所以如果你的输入以
`... WHERE 'b'LIKE'b` 结尾，拼起来就是：

```sql
... WHERE 'b'LIKE'b%'
```

`'b'LIKE'b%'` 是一个完整、恒真的表达式 —— 尾部那两个字符被你"用掉"了，
不需要注释。

### 规则 2：`(?i)union select` —— 只认一个空格

这是这一题最值得学的一条。

规则作者的意图是"拦 `union select`"。但 `r"union select"` 是一个**字面量**：
它匹配的是 u-n-i-o-n-空格-s-e-l-e-c-t 这 12 个字符。

而 SQL 的语法要求不是"一个空格"，是**任意空白**。SQLite 认这些：

| 写法 | URL 编码 | 能过这条规则吗 |
|---|---|---|
| `UNION SELECT` | `%20` | 不能（正好命中） |
| `UNION  SELECT` | `%20%20` | **能** |
| `UNION\tSELECT` | `%09` | **能** |
| `UNION\nSELECT` | `%0A` | **能** |
| `UNION\r\nSELECT` | `%0D%0A` | **能** |
| `UNION/**/SELECT` | 原样 | **能**（但会被规则 1 拦掉） |

两个空格就够了。

> **教训：别用字面量描述攻击特征。**
>
> `"union select"` 描述的是"u,n,i,o,n,空格,s,e,l,e,c,t"。
> `union` + 任意空白 + `select` 才是**结构**。
>
> 这就是为什么正则要写 `(?i)union\s+select` —— 但即使这么写也还不够，
> 因为 `/**/` 在 SQL 里也是空白，而 `\s` 不匹配 `/`。

### 规则 3：`(?i)\b(or|and)\b` —— 封了布尔运算

`OR` / `AND` 用不了了。但 SQLite 里还有别的办法让条件成立：

- **`LIKE`**（这一题用的）：`'b'LIKE'b%'` 恒真
- **`GLOB`**：`'b' GLOB 'b*'`
- **`=`**：`'b'='b'`
- **`||`**（字符串拼接，不是布尔运算，不受影响）

但这里有个很容易踩的细节：**模板在你输入的后面还会追加 `%'`。**
所以你不能直接写 `'b'='b'` —— 拼起来会变成 `'b'='b'%'`，语法就不对了。

每个运算符都要让"追加的那两个字符"接上去仍然成立：

| 运算符 | 你输入的结尾 | 追加之后 | 成立吗 |
|---|---|---|---|
| `LIKE` | `'b'LIKE'b` | `'b'LIKE'b%'` | 成立 |
| `=` | `'b%'='b` | `'b%'='b%'` | 成立 |
| `GLOB` | `'b'GLOB'b*` | `'b'GLOB'b*%'` | 成立（`b*%` 能匹配 `b`） |
| `=`（写错） | `'b'='b` | `'b'='b%'` | **不成立** |

「payload 要贴着目标查询的实际形状来写」——这个细节本身就是这一题的一部分。

### 规则 4：`(?i)sqlite_` —— 拦住读库结构

想摸清有哪些表，常规做法是查 `sqlite_master`。现在被拦了。

绕法：
- 表名可以猜（这一题叫 `users`）
- `sqlite_master` 可以用大小写变体吗？**不行**，`(?i)` 已经吃掉了大小写
- 但可以从别的地方拿表名：应用的报错（这一题不给）、前端 JS 里写死的接口名、
  API 文档、`/* */` 里被注释掉的旧查询
- 也可以不查结构，直接用 `UNION` 猜列数（`ORDER BY n` 或
  逐步加 `,1` 直到列数对上）

**注意规则 4 没有用 `\b` 也没有用 `\s`** —— 它只是子串匹配 `sqlite_`，
所以连 `my_sqlite_thing` 这种也会被拦。这又是一个"规则比它想拦的东西更宽"的例子。

## 怎么打通

```
x' UNION  SELECT username,password,role FROM users WHERE 'b'LIKE'b
```

拼进模板之后：

```sql
SELECT name, dept, ext FROM staff
WHERE name LIKE '%x' UNION  SELECT username,password,role FROM users WHERE 'b'LIKE'b%'
```

- 前面那个 `LIKE '%x'` 什么都匹配不到
- `UNION` 后面三列对上 `staff` 的三列
- `WHERE 'b'LIKE'b%'` 恒真 → users 的行全出来

然后去页面上把读到的密码提交掉。

## 拦截 vs 删除：两种过滤器的绕过思路完全不同

这一题用的是**拦截**（命中就不执行）。还有一类过滤器是**删除**：

```python
# 删掉它认识的东西，然后照常执行
value = re.sub(r"(?i)<script>", "", value)
```

这两类要绕的东西不一样，值得记住：

| | 拦截（block） | 删除（strip） |
|---|---|---|
| 目标 | 让规则**匹配不到** | 让删除之后**又拼回来** |
| SQli 例子 | `UNION  SELECT`（双空格） | `UN/**/ION`（如果删的是 `/**/`） |
| XSS 例子 | `<svg/onload=...>` | `<scr<script>ipt>` |
| 典型错判 | 把"字面量"当"结构" | 用 `re.sub` 处理嵌套 |

**"删除"比"拦截"危险得多**，因为删除是可逆的 —— 攻击者可以构造
"删掉之后正好拼出危险内容"的输入。这也是为什么正确做法是
**输出时按上下文转义**，而不是"输入时删掉坏东西"。

（`xss/tag_filter` 那道题就是删除式过滤器。）

## 现实里的 WAF 绕过

这一套思路搬到真 WAF 上，多出来的维度是：

| 维度 | 说明 |
|---|---|
| **编码层数不一致** | WAF 解码一次，后端解码两次 → `%2527`（见 `path_traversal/encoding_filter`） |
| **参数污染** | `?a=clean&a=evil` —— WAF 看第一个，后端用最后一个 |
| **Content-Type** | WAF 只查 `application/x-www-form-urlencoded`，你发 `application/json` |
| **分块传输 / HTTP/2** | WAF 解析不了的分块，后端能解析 |
| **大小写与空白** | 这一题的规则 2 |
| **等价语法** | 这一题的规则 3（`OR` → `LIKE`） |
| **注释当空白** | `/**/` |
| **超长 padding** | 撑过 WAF 的检测窗口 |

**最关键的一条**：WAF 是**签名**匹配，它描述的是"已知的攻击长什么样"。
只要你构造出一个"语义等价、但签名不匹配"的 payload，它就没用了。
所以 WAF 只能当纵深防御，**永远不能替代参数化查询**。

## 怎么修

**参数化查询。** 过滤的关键词黑名单在这上面一点用都没有：

```python
con.execute(
    "SELECT name, dept, ext FROM staff WHERE name LIKE ?",
    ("%" + keyword + "%",),
)
```

如果确实需要一层关键词过滤（比如合规要求），那要注意：

1. **别用它当主要防线** —— 它是补丁，不是墙
2. **规则要描述结构，不要描述字面量**：`(?is)union\s+select` 而不是 `union select`；
   而且要知道 `\s` 不含 `/**/`
3. **拦截页不要回显命中的规则名**（这一题是教学需要才回显的）——
   真实环境里那等于给攻击者一份地图
4. **规则要测**：拿一份绕过字典跑一遍，看看漏多少
