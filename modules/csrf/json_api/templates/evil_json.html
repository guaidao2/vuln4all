整点福利，先到先得

这是一张攻击者放的页面。它看起来在发福利，实际上页面一打开， 它就用你的浏览器去提交了一个改邮箱的请求。

它是怎么发出的

改邮箱的接口只收 application/json。HTML 表单发不出这个类型 —— 但它能发 text/plain，而 text/plain 的表单编码 不对字段名做任何转义。于是把 JSON 的开头和结尾分别塞进 name 和 value，拼出来的整段 body 正好就是一段合法 JSON： 

<form action="{{ target }}" method="POST" enctype="text/plain">
  <input name='{{ field_name }}' value='"}'>
</form>
<script>document.forms[0].submit()</script>

实际发出的请求体：
{"email":"{{ evil_email }}","ignore":"="}
                      ↑ 表单的那个等号变成了 ignore 字段的值

服务端不看 Content-Type 就把请求体当 JSON 解析，所以它照单全收。

手动触发：

接下来

  1. 回到 个人中心，看你的邮箱变成了什么
  2. 全程你都没点过「保存」

注意：text/plain 是 CORS 允许的"简单类型"，所以浏览器 不会先发预检请求（OPTIONS）—— 这也是这个手法能成立的原因之一。
