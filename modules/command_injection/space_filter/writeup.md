# 带分隔符过滤的命令注入

## 这一题在教什么

**黑名单漏一个字符就等于没防。**

过滤器列得很认真：

```python
RULES = [
    ("空格与制表符", r"[ \t]"),
    ("分号",         r";"),
    ("管道与后台",   r"[|&]"),
    ("反引号",       r"`"),
    ("命令替换",     r"\$\("),
    ("重定向",       r"[<>]"),
]
```

它背后的假设是：命令注入得靠分隔符把两条命令接起来。这个假设不算错 ——
但它漏了两件最基础的事。

## 漏的第一件：换行

`127.0.0.1; id` 会被「分号」那条拦掉。但 shell 里**换行跟分号完全等价**：

```
127.0.0.1%0Aid
```

`%0A` 是 URL 编码的换行，Flask 解码之后就是一个真正的换行符。

过滤器列了 `;`、`|`、`&`、反引号、`$(` —— 唯独没列换行。
**它列了一份"分隔符"清单，然后漏掉了最基础的那个。**

> 顺带说：空行也管用。`127.0.0.1\n\nid` 一样能跑。

## 漏的第二件：空格有替代品

命令行要跑别的命令，总得有个空格分隔命令名和参数。过滤器把空格和制表符都拦了。

但 shell 里有一个"本身就是一个空白字符"的变量：

```bash
${IFS}
```

`IFS` 是 Internal Field Separator，它的默认值就是
**空格 + 制表符 + 换行**。所以 `${IFS}` 展开出来就是空白。

```
127.0.0.1%0Ahead${IFS}-c${IFS}20${IFS}/etc/hostname
```

完整 payload：

```
127.0.0.1%0Ahead${IFS}-c${IFS}2000${IFS}<凭据文件的完整路径>
```

页面下半部分会把数据目录和那个文件的完整路径告诉你。

## 这个环境（dash）里能跑和不能跑的写法

`/bin/sh` 在这台机器上是 **dash**，不是 bash。这个区别很重要，
因为下面这些"经典写法"是 **bash 专属**的，在这里会报错：

| 写法 | 用途 | 在 dash 下 |
|---|---|---|
| `${IFS}` | 替空格 | **可用** |
| 真制表符 `%09` | 替空格 | 可用（但过滤器拦了） |
| `$(printf${IFS}"\040")` | 用命令替换生成空格 | **可用** |
| `` `printf${IFS}' '` `` | 反引号版 | 可用（但反引号本身被拦了） |
| `head${IFS}-c${IFS}20${IFS}/etc/host*` | 通配符省掉参数 | **可用** |
| `${IFS:0:1}` | 取变量子串当空格 | **不可用**（`Bad substitution`） |
| `{-c,20}` | 花括号展开 | **不可用** |
| `$'\x20'` | ANSI-C 引号 | **不可用** |

**这一条本身就是要教的东西**：别背 payload。
payload 是"针对某个环境"的，换个 shell 就可能失效。

> 侦察的第一步永远是：**这是哪个 shell？**
> `echo $0`、`ls -l /bin/sh`、看报错里的前缀（dash 会报 `/bin/sh: 2: ...`，
> bash 会报 `bash: line 2: ...`）。

## 顺带：还有一种绕过完全不靠分隔符

如果命令是 `ping -c 1 <input>` 这种**不带引号**的拼接，那不接新命令也能搞事 ——
你可以直接往 `ping` 塞额外的参数。经典的是用 `ping` 的 `-p` 或者
其他工具的参数做文件读取/写文件（取决于目标程序自己支持什么）。

这条路子在这道题里被"必须换行才能接新命令"限制了，但在真实环境里
`shell=True` 的拼接往往连参数都能被改写 —— 值得记住。

## 判定为什么看"执行日志"

这一题的通关条件是"读到内部资料里的凭据"。判定不是去猜学习者发了什么请求，
而是**读应用自己写的执行记录**：那个文件里出现了凭据那串东西，就说明
命令真的执行了、文件真的被读了。

`check()` 里没有请求上下文，所以它只能从**已经落盘的状态**推 ——
而这个业务场景本来就会记执行日志，所以判定载体是应用本来就有的东西，
不是为判定另加的一份进度。

## 怎么修

**一、命令参数要是参数，不是字符串。**

```python
import ipaddress
import subprocess

# 能用库就别起进程
ipaddress.ip_address(target)

# 非要起进程，就传参数列表，让 shell 根本没机会介入
subprocess.run(["ping", "-c", "1", "--", target],
               shell=False, capture_output=True, text=True, timeout=10)
```

三个细节：

- `shell=False`（默认值）—— 这是关键，参数不会被 shell 解析
- `--` —— 告诉命令"后面的都是参数，不是选项"，防止 `-` 开头的注入
- `timeout=` —— 别让一条 `sleep 9999` 挂住 worker

**二、真要校验，用白名单而不是黑名单。**

```python
try:
    ipaddress.ip_address(target)
except ValueError:
    abort(400)
```

**解析成结构化类型再判断**，而不是"扫描字符串里有没有危险字符"。
IP 地址是一个有明确语法的东西，用它自己的解析器。

> 这一题的黑名单有 6 条规则，漏了 1 个字符就全废。
> 白名单只需要 1 条规则，而且漏不掉。

**三、别用 `os.system` / `shell=True`。**

理由和"别用 `re.sub` 做安全过滤"是同一个：它们把一个**结构化**的东西
（命令 + 参数列表）降级成了**字符串**，而降级过程是有损的 ——
你没法在字符串里区分"这是数据"和"这是语法"。

**四、能不起进程就不起。**

`ping` 这种需求，用 Python 的 `socket` 或者 `icmplib` 就能做。
少一个外部命令，就少一整个攻击面。
