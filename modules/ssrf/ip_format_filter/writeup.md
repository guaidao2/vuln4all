# 带 IP 字面量黑名单的 SSRF

## 这一题在教什么

**地址不是字符串。**

这是 SSRF 防护里最典型的一个坑：作者把"地址"当成了"字符串"，
于是写出一份枚举各种写法的黑名单。但**同一个地址的表示形式有无穷多种，
而它的语义只有一个**。

黑名单枚举的是表示形式，决定请求去哪的是语义。这两者之间的差距就是绕过空间。

跟另一道 SSRF 题（`ssrf/url_preview`）的区别：

| | `ssrf/url_preview` | 这一题 |
|---|---|---|
| 过滤的是什么 | **主机名**（白名单子串匹配） | **IP 字面量**（黑名单） |
| 绕过靠什么 | 把内部地址塞进 `@` 前面的用户信息位置 | 换一个 IP 的**写法** |
| 教的东西 | `@` 在 URL 里的含义 | IP 地址的多种表示 |

## 过滤层

```python
RULES = [
    ("回环地址字面量", r"(?i)\blocalhost\b|\b127\.0\.0\.1\b|\b0\.0\.0\.0\b|::1"),
    ("私有网段字面量", r"\b10\.\d{1,3}\.\d{1,3}\.\d{1,3}\b"
                       r"|\b192\.168\.\d{1,3}\.\d{1,3}\b"
                       r"|\b172\.(1[6-9]|2\d|3[01])\.\d{1,3}\.\d{1,3}\b"),
    ("内网主机名后缀", r"(?i)\.local\b|\.internal\b|\.lan\b"),
]
```

匹配的是 URL 里的 host。写得挺认真 —— 私有网段三段都列了。

## 关键：IP 地址有非常多种写法

`127.0.0.1` 作为一个 32 位整数是 `2130706433`。所以：

| 写法 | 说明 |
|---|---|
| `127.0.0.1` | 标准的点分十进制 |
| `127.1` | 省略后三段，等价于 `127.0.0.1` |
| `2130706433` | 整个 32 位整数 |
| `0x7f000001` | 十六进制 |
| `017700000001` | 八进制 |
| `0` | 等价于 `0.0.0.0`，在 Linux 上连它等于连本机 |
| `::ffff:7f00:1` | IPv4 映射的 IPv6，十六进制形式 |

**这些全都能连到 127.0.0.1**，而黑名单一条都不认识。

### 为什么能成

`socket.getaddrinfo()` 用的是和 `inet_aton()` 同一套解析规则：
它接受十进制 / 八进制 / 十六进制的整数形式，也接受缺段的简写。

前端（或者浏览器）也一样 —— 你在浏览器地址栏输入 `http://2130706433/`
一样会打开本机页面。

### 一个容易踩的细节

`[::ffff:127.0.0.1]` 这种 IPv6 写法**不行** —— 字符串里带着 `127.0.0.1`，
第一条规则照样拦得到。

要写成 `::ffff:7f00:1`（同一个地址的十六进制形式）才行。

「差一点就被拦」这种细节，自己试的时候最容易踩 —— 所以试的时候要
**看过滤器的报错**，而不是猜。

## 怎么打通

页面上给了内网后台的完整地址。把它换成上面任意一种写法：

```
http://2130706433:8800/intranet/
http://0x7f000001:8800/intranet/
http://017700000001:8800/intranet/
http://127.1:8800/intranet/
http://0:8800/intranet/
http://[::ffff:7f00:1]:8800/intranet/
```

预览结果里出现内网后台的令牌就通关了。

## 跟表示形式无关的另外三类绕过

IP 写法只是其中一类。SSRF 的绕过还有几条路，值得一起记住：

### 一、302 重定向（校验和请求不是同一个目标）

```
你 → 预览服务："http://我的公网服务器/x"
预览服务 → 我的服务器       （校验：公网地址，放行）
我的服务器 → 302 Location: http://127.0.0.1:8800/intranet/
预览服务 → 127.0.0.1        （跟着跳，**不再校验**）
```

这一题的预览服务跟 3 跳重定向，而且不对跳转目标重新做校验 —— 所以这条路也能走通。
配置里写的是"允许跳转"但没有"跳转后重新校验"，就是这个问题。

### 二、DNS 重绑定（校验和连接不是同一个时刻）

域名第一次解析到公网 IP（通过校验），第二次解析到内网 IP（真正连接时）。
校验和连接之间有**时间差**，攻击者在两次解析之间切换 DNS 记录。

防御要在这里做：**校验时解析出来的 IP，和实际连接用的 IP 必须是同一个**。
把解析结果缓存起来传给连接函数，而不是让连接函数自己再解析一次。

### 三、`@` 混淆

```
http://127.0.0.1@evil.com/     ← 你以为连的是 127.0.0.1？其实连的是 evil.com
http://evil.com@127.0.0.1/     ← 反过来的这个才是真的连 127.0.0.1
```

`@` 前面是**用户信息**，后面才是主机。`urlparse` 的 `hostname` 拿到的是
`@` 后面的那个。这道题的黑名单用的是 `hostname`，所以这条路被堵住了 ——
但它在手写解析 URL 的代码里非常常见。（`ssrf/url_preview` 就是这一类的题。）

## 怎么修

**一、解析出 IP，按 IP 的类型判断。**

```python
import ipaddress
import socket

host = urlsplit(url).hostname
# 拿到真正要连的 IP（这一步会把所有写法都归一化）
infos = socket.getaddrinfo(host, None)
for info in infos:
    ip = ipaddress.ip_address(info[4][0])
    if ip.is_private or ip.is_loopback or ip.is_link_local or ip.is_reserved:
        abort(403)
```

**关键**：`ipaddress` 会把 `2130706433`、`0x7f000001`、`127.1`
全部归一化成 `127.0.0.1`，然后你判断的是**它是哪一类地址**，
而不是"它的字符串长什么样"。

**二、白名单比黑名单可靠得多。**

```python
ALLOWED_HOSTS = {"api.github.com", "cdn.example.com"}
if host not in ALLOWED_HOSTS:
    abort(403)
```

域名精确匹配 —— 不要用子串，也不要用"以 xxx 结尾"（那会被
`api.github.com.evil.com` 绕过）。

**三、连接与校验要"绑定"。**

即使解析正确了，也还有一个 TOCTOU 问题：校验时解析到公网，
连接时又解析了一次，中间可能被换掉（DNS 重绑定）。

解法是**只解析一次**：把解析得到的 IP 直接传给连接层，
并让 HTTP 客户端的 `Host` 头保持原域名。

```python
ip = socket.gethostbyname(host)      # 只解析这一次
check_ip(ip)                          # 检查这个 IP
conn = http.client.HTTPConnection(ip, port)   # 连的也是这个 IP
conn.request("GET", path, headers={"Host": host})
```

**四、重定向必须重新校验。**

```python
if resp.status in (301, 302, ...):
    location = resp.getheader("Location")
    # 别直接跟 —— 把它当一条新的 URL，从头走一遍校验
    return fetch_validated(location)
```

**五、网络层兜底。**

- 让预览服务跑在独立的网络命名空间 / 容器里，只允许出站到公网
- 内网服务要求认证（这一题的内网后台**没有任何认证** —— 这就是 SSRF
  能拿到东西的原因。纵深防御里，"内网 = 可信"这个假设本身就该被质疑）
