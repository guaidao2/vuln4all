密钥是怎么管的

当前活跃的 kid{{ active_kid }}
密钥目录{{ keys_dir }}

为了支持密钥轮换，签名密钥按名字存在一个目录里， token 头部的 kid 字段告诉服务端用哪一把。 这个设计本身是合理的 —— 真实的 JWT 实现都这么干。

问题在实现上：那个 kid 值被直接当成了文件路径。 所以先想清楚一件事 —— 它最终会被拿去干什么？

跟另一道 JWT 题的关系

jwt/alg_none 那道题是「验签算法 从 token 自己声明的 alg 里读」，这一道是「验签密钥从 token 自己声明的 kid 里推」。

两道的共同点是一句话：安全决策的参数不该由被验证的对象自己提供。
