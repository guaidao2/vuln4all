怎么验证这一题

这个靶场是单进程单源，在浏览器里构造不出真正的跨源请求 —— 所以用 curl 看响应头，这也正是你手工确认 CORS 配置时该用的办法： 

curl -i -H 'Origin: https://evil.example' \
     -b 'session=<你的 Cookie>' '{{ api_url }}'

curl -i -H 'Origin: {{ legit }}' \
     -b 'session=<你的 Cookie>' '{{ api_url }}'
{% if origin %}

这次请求带的 Origin 是 {{ origin }}。 响应头在下面的 curl 输出里能直接看到。

{% endif %}

要找的是这两个头同时出现、而且指向一个不是你自己的源

Access-Control-Allow-Origin: <某个 Origin>
Access-Control-Allow-Credentials: true

这两个凑在一起，才等于"浏览器，你可以让那个源的 JS 带着用户的 Cookie 读这个响应"。少一个都不行 —— 所以 CORS 的洞要看两个头的组合， 不能只看 ACAO。
